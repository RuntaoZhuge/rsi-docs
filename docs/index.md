# 安全自我进化的收益，能否经受后续正常能力自我进化？

> **通过动态安全自我改进获得的防御收益，在模型随后使用新数据继续训练、提高正常任务能力时，能否持续保留？**

这是本项目目前唯一需要回答的问题。本站发布该问题的动机梳理、实验设计（任务书）、实验进度与结果，以及研究动机幻灯片。

!!! note "内容边界"

    本站已发布 **G0–G5 的完整实测结果**（seed-1）；第二 seed 尚未运行。文中出现的模型名、指标名与阈值规则都是待验证的实验安排；`M0`、`S1` 的安全性与编程能力，`LoRA-SFT` 是否提升能力，安全收益是否下降，都必须按 G1–G5 实测后由《[实验进展与结果](results.md)》页给出。

## 研究问题从哪里来

两组已有文献支撑这个问题，但它们只提供**前提**，不提供**结论**：

| 已有证据 | 支持的事实 | 在本研究中的角色 |
|---|---|---|
| Self-RedTeam、TriPlay-RL、AdvGame 等动态安全自我进化工作 | 安全能力可以通过在线自博弈／攻防共进化被持续增强 | 说明"新增安全收益"是真实存在、值得单独考察的对象 |
| ICLR 2024 微调危害安全、ICML 2025 良性异常样本、AAAI 2026 Agentic 微调失配 | 后续正常能力的训练可能削弱此前建立的安全对齐 | 说明"安全改进完成时"与"后续能力更新后"是两个不同的状态 |

因此，尚未被系统回答的是：**安全自我进化刚获得的增益，在之后以能力为目标的持续更新中还能剩下多少。** 详见《[研究动机](motivation.md)》。

## 实验主线：两个阶段、两条分支

```text
              同一原始模型 M0 = Qwen2.5-7B-Instruct
                        │
          ┌─────────────┴─────────────┐
          │                           │
     不额外安全训练              动态安全改进 S（S1: Self-RedTeam）
          │                           │
         M0                          S1
          │                           │
   同一 KodCode 训练集           同一 KodCode 训练集
   同一 LoRA-SFT 配置           同一 LoRA-SFT 配置
          │                           │
     B1 → B2 → B3               C1 → C2 → C3
```

- **S 阶段（安全能力增强）：** 照原作者论文与代码获得安全增强模型，不擅自改动其训练配置。
- **U 阶段（后续正常能力更新）：** 用固定 10K 的 KodCode-V1-SFT-R1 子集做统一 **LoRA-SFT**，这是唯一的能力更新方式，不是再跑一套 RSI 算法。

两条分支的意义：只有同时观察 `S1 → C1/C2/C3` 与 `M0 → B1/B2/B3`，才能判断 S 阶段额外获得的安全优势在相同后续更新之后还剩多少。

## 主要指标

| 指标 | 方向 | 说明 |
|---|---|---|
| HarmBench ASR | 越低越安全 | 统一的攻击成功率协议，`G(t) = ASR(B_t) - ASR(C_t)` |
| LiveCodeBench pass@1 | 越高越好 | LCB DEV 用于过程判断，LCB TEST 仅在协议冻结后报告 |
| XSTest 过度拒绝率 | 越低通常越好 | 避免把"一律拒绝"误当成安全增强 |

安全收益保留率 `R(t) = G(t) / G(0)` 与安全模型自身退化幅度 `D(t) = ASR(C_t) - ASR(S1)` 必须一起报告；`G(0)` 很小或噪声很大时不解释比值。完整定义见《[实验方案](experiment.md)》第 8 节。

## 关口进度

实验按关口放行，未通过不得进入下一步。当前状态以《[实验进展与结果](results.md)》页为准；运行环境与工具链的确认记录见《[执行环境与进度](environment.md)》。

| 关口 | 内容 | 状态 |
|---|---|---|
| G0 | 权重、数据、评测器、资源核查 | ✅ 完成 |
| G1 | `M0` / `S1` 安全前测（HarmBench + XSTest） | ✅ **通过**（G(0)=13.6pp） |
| G2 | `M0` / `S1` 编程能力前测（LCB DEV） | ✅ 通过（9.8% / 6.0%） |
| G3 | 小样本 LoRA 试训，确认能力训练有效 | ✅ 通过（+22.2 / +23.2pp） |
| G4 | 正式 LoRA 更新，逐 epoch 保存与评估 | ✅ 完成（3 epoch × 2 分支） |
| G5 | 汇总分析、收益保持结论 | ✅ 完成（锚点未漂移） |
